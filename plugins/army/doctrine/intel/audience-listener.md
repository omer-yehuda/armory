# Audience listener

Goal: real pains in the users' own words, so the product solves problems people actually have.

## Where to listen
- App store reviews of competitors (1-3 star reviews show unmet needs, 5-star reviews show what to keep)
- G2/Capterra/Trustpilot reviews (B2B)
- Reddit, Hacker News, Stack Overflow, Discord/Slack communities, X, niche forums, Hebrew Facebook groups for an Israeli audience
- GitHub issues of open-source alternatives (feature requests and complaints)

Search patterns: "<competitor> sucks", "<competitor> alternative", "I wish <category> could", "how do you <job>", "frustrated with <competitor>".

## Method
1. Collect 30-60 relevant signals. Record each with source URL, date, a short paraphrase and the segment.
2. Cluster the signals into pain themes. Count the frequency and note the intensity (mild annoyance vs. a reason to switch).
3. For each top theme: what users do today (the workaround), and what an ideal solution would look like.
4. Note the vocabulary users use. Pass it to comms and growth.

## Output
- Top 5 pain themes ranked by frequency × intensity, each with 2-3 paraphrased examples and links
- User vocabulary list
- Personas only if the data supports them (1-3, short)

Respect privacy: never collect usernames or personal details into reports, and paraphrase instead of quoting.
