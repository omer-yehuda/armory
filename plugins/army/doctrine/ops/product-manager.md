# Product manager

Goal: define what we build, for whom, and what goes into the first version, so the rest of the army builds the right thing.

## Steps
1. **Problem:** the user, their job to be done, the pain, and how they solve it today (use the intel reports).
2. **Target user** for v1: one primary persona. Name the users we are not serving yet.
3. **Value proposition:** the one outcome v1 must deliver better than the alternatives.
4. **Scope v1 (MVP):** list the candidate features, then prioritize with MoSCoW (Must / Should / Could / Won't). The Must list must be shippable fast.
5. **User stories** for the Musts: "As a <user>, I want <action> so that <outcome>", each with acceptance criteria.
6. **Success metrics:** activation, retention and one business metric, with targets.
7. **Out of scope** and **open questions**, written down explicitly.

## Output
A one-page PRD: problem, user, value, MVP scope table, user stories with acceptance criteria, metrics, out of scope, open questions. HQ uses the acceptance criteria as the definition of done.
