Give Claude a mission, not a prompt.

Army is a Claude Code plugin. A Chief of Staff asks its briefing questions once, then plans the mission and dispatches specialist units as subagents, each on the most cost-effective model for its job.

Install

/plugin install army --marketplace omer-yehuda/plugins
raise the army <your mission>
Claude Code 2.1.275+. Older versions: /plugin marketplace add omer-yehuda/plugins, then /plugin install army@omer-plugins.
Chief of Staff (HQ)

Briefs you once, writes the operation order, dispatches units in parallel, enforces the safety gates, integrates the results and reports back.

Mission details

Muster

Loads your mode, safety gates and this project's lessons-learned memory.

Briefing

Asks all its questions in one round. After that it runs on its own.

Recon

A cheap Haiku scout maps the codebase once per commit, so no unit explores twice.

Operation order

Intent, definition of done, units, phases and models, written to disk.

Dispatch

Independent units run in parallel. Each loads only the playbooks it needs.

Safety gates

Pushes, deploys, deletions and new dependencies wait for your approval.

Integrate

Reads 200-word SITREPs. Blocking findings loop back for a fix and re-check.

Inspection

An Inspector General who never saw the work judges the result cold.

After-action

History records lessons, so the next mission in this project starts smarter.

Local memory

.army/ ├─ state.json active mission ├─ recon.md codebase map ├─ lessons.md read every mission └─ missions/<id>/ ├─ opord.md ├─ <unit>.md full reports └─ log.md

Excluded from git automatically through .git/info/exclude. Never committed.

Safety gates (default on)

  • git push, history rewrites, discarding changes
  • Deleting files or dropping data
  • Deployments and infrastructure changes
  • Publishing packages
  • Installing new dependencies
  • Messages to external people or services

Enforced by a PreToolUse hook during missions. Toggle with /army:gates.

Token discipline

  • One subagent per unit; specialists are playbooks loaded on demand
  • Full reports on disk, 200-word SITREPs to HQ
  • Recon cached per commit; lessons capped at ~100 lines
  • Lean mode: Sonnet and Haiku only
  • Thin work gets one targeted re-brief, not a retry loop
